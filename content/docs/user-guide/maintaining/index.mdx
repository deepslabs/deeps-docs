## Create a Wallet Account

Create a dedicated account in an EVM-compatible wallet such as MetaMask. Store its recovery phrase and private key securely; never include either value in support requests or public logs.

## Connect to the Server over SSH

Use the account credentials configured when the server was provisioned and the public IPv4 address assigned by the cloud provider.

**Option 1.** The built-in system terminal:

* On macOS and Linux, use the built-in terminal.
* On Windows, use PowerShell with the OpenSSH client. See [Get started with OpenSSH for Windows](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse?tabs=powershell).

Run `ssh username@public_ip_address`, for example `ssh test@1.1.1.1`, and enter the password when prompted.

**Option 2.** Third-party SSH login tools:

You can also use an SSH client such as Xshell, PuTTY, SimpleRemote, or Termius. Follow the security and connection guidance provided by the selected client.

**Option 3.** The built-in server method of cloud service:

Most cloud providers offer a browser-based server console. Consult the provider's documentation for connection instructions.

## Install the Runtime Environment

```bash
# Install the Docker runtime environment
sudo curl -fsSL https://get.docker.com | bash -s docker
sudo systemctl enable docker
sudo systemctl start docker

# Check if the Docker service started correctly
sudo systemctl status docker
# Press Ctrl+C to exit the status view
sudo chmod 666 /var/run/docker.sock
docker version

# Download the docker-compose program
sudo curl -L "https://github.com/docker/compose/releases/download/1.29.2/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose

# Install docker-compose
sudo chmod +x /usr/local/bin/docker-compose
docker-compose --version
```

## Create the Node Storage Directory and Compose File

<Callout>
Advertising the node's public address improves peer connectivity and DHC stability.

```
--public-addr <PUBLIC_ADDR>...
    Public address that other nodes will use to connect to this node.
    This can be used if there's a proxy in front of this node.
    PUBLIC_ADDR example: "/ip4/8.8.8.8/tcp/30333"
```
</Callout>

```bash
# Create a node storage directory
mkdir -p deeps-testnode/node-data

# Enter the node directory
cd deeps-testnode

# Adjust user permissions
chmod 777 node-data

# Add a configuration file
cat > docker-compose.yaml <<EOF
version: "3"
services:
  node1:
    image: deepslabs/deeps-node:pre-beta
    restart: always
    environment:
      RUST_LOG: info
    volumes:
    - "./node-data:/data"
    command: |
      --validator
      --enable-offchain-indexing true
      --rpc-methods Unsafe
      --unsafe-rpc-external
      --rpc-cors all
      --rpc-max-connections 100000
      --pool-limit 100000
      --pool-kbytes 2048000
      --tx-ban-seconds 600
      --ethapi=debug,trace,txpool
      --chain testbeta
      --public-addr <PUBLIC_ADDR>
    ports:
      - 9944:9944
      - 30333:30333
EOF

# Start the service
docker-compose up -d
```

Initial block synchronization can take some time.

Run `docker-compose logs -f --tail 200 | grep finalized` and compare the `finalized` and `target` heights. The node is synchronized when the finalized height reaches the target height.

<Callout>
YAML is indentation-sensitive. If Docker Compose reports a parsing error, verify that the copied file uses consistent spaces and preserves the indentation shown above.
</Callout>

## Configure the SGX Server

```bash
# Return to the parent directory
cd ..

# Clone the deployment repository
git clone https://github.com/deepslabs/deeps-mining-scripts.git

# Install SGX dependencies
sudo apt update
sudo apt install build-essential automake autoconf libtool wget libssl-dev dkms
wget https://download.01.org/intel-sgx/latest/linux-latest/distro/ubuntu18.04-server/sgx_linux_x64_driver_1.41.bin
bash sgx_linux_x64_sdk_2.30.101.1.bin

# Check SGX status
cd deeps-mining-scripts && ./sgx-detect
```

## Configure `keyring.toml`

Confirm the current DHC bootnode addresses and update the configuration if they have changed.

<Callout>
Set **`external_multiaddrs`** to advertise the server's public address and improve inbound connectivity.

```
example: external_multiaddrs = ["/ip4/127.0.0.1/tcp/38700"]
```
</Callout>

### Generate the Keyring Configuration

```shell
hdc config testnet <owner address>
```

## Update the Compose Image Version (Optional)

Replace `<version_no>` only when an updated image is published. Check the [official Compose file](https://github.com/deepslabs/deeps-mining-scripts/blob/master/docker-compose.yml) for the supported version.

<Callout>
**Before changing version numbers, make sure your device is in Standby status, or not registered. Otherwise, you will be punished.**
</Callout>

Check the [official Compose file](https://github.com/deepslabs/deeps-mining-scripts/blob/master/docker-compose.yml) for the current image version.

```yaml
# vim docker-compose.yaml

version: "3"
services:
  occlum-keyring:
    image: deepslabs/deeps-occlum-keyring:<version_no>
    restart: always
...............
```

## Start the DHC Service

```bash
# Start DHC service
docker-compose up -d

# View node service logs
docker-compose logs --tail 200 -f

# Check P2P connection logs
docker-compose logs --tail 200 -f | grep 'Current peers'
```

## Update the Device Version

Keep the DHC server on the latest supported image version.

#### 1. Exit the Service

Device upgrades must be performed while the device is in **Standby**.

If the device is **Serving**, exit the service before starting the upgrade. If it is **Exiting**, wait up to one day for the exit to complete.

#### 2. Update the Script File

```bash
# Shut down the script and back up your data
docker-compose down && mv data/ data-bak/

# Replace the image version of the device
# 1.0.x is your current version and 1.0.1 is the latest version
sed -ri 's/1.0.x/1.0.1/g' docker-compose.yaml

# Restart the service
docker-compose up -d
```

Verify the device version in the [DHC Explorer](https://test-dhcs.deeps.fi/).

#### 3. Rejoin the Service

After completing the upgrade, rejoin the service and wait for the device to enter **Serving**.

#### 4. Remove Backup Data (Optional)

```bash
rm -rf data-bak/
```
