## Node Initialization

### Using Docker

**Docker** is currently the supported method for running a DeepS beta-testnet node. Start a node with the image published by the DeepS team:

```shell
docker run -p 30333:30333 deepslabs/deeps-node:pre-beta --chain=testbeta --validator
```

Add `-d` to run the container in the background.

Add `-v ./node-data:/data` to persist node data on the host.

To expose RPC services to external applications such as Polkadot.js, add the following flags:

* `--unsafe-rpc-external`: Listen to all RPC interfaces.
* `--unsafe-ws-external`: Listen on all WebSocket interfaces.

<Callout type="warn">
These flags expose unsafe RPC methods. Restrict access with a firewall or reverse proxy, and never expose the endpoints directly to the public internet.
</Callout>

More details can be found by executing the following command:

```shell
docker run --rm deepslabs/deeps-node:pre-beta --help
```

### download Snapshot

To avoid syncing the chain from genesis, you can download a chain snapshot and start the node with pre-synced data:

```shell
wget -c -O node-data.tar https://testnet-download.deeps.fi/node-data
```

The `-c` flag enables resume support, so the download can continue from where it stopped if interrupted.

After the download completes, extract the archive into the node data directory:

```shell
tar -xf node-data.tar
```

Then start the node with the data directory mounted:

```shell
docker run -p 30333:30333 -v ./node-data:/data deepslabs/deeps-node:pre-beta --chain=testbeta --validator
```

The node will start from the snapshot height instead of syncing from genesis, which significantly reduces the initial sync time.

## FAQ

#### Why are nodes out of sync?

If the peer count is unstable or repeatedly drops to zero, forward TCP port `30333` from the router's public IP address to port `30333` on the node's internal IP address. Ensure that the firewall permits inbound connections on this port.
